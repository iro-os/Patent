## 0. 한 장 요약 (핵심 결론)

**우리와 GenIP은 "같은 제품의 완성도 차이"가 아니라, 서로 다른 강점을 가진 두 제품이다.**

- **GenIP = 우리 플랜의 "Phase 2"(문서 생성·편집·내보내기)를 완성한 셀프서브 상용 SaaS.** 단, 선행기술 리서치·근거·커버리지 화면이 **전혀 없다**(46초 영상에 검색/근거 UI 0회 노출).
- **우리 = 우리 플랜의 "Phase 1"(선행기술 리서치 + 차별성 분석 + 근거 grounding + 정직한 커버리지)을 완성한 MVP.** 단, 사용자가 "보는" 부분(본문 자동생성·섹션 편집·DOCX 내보내기)이 **아직 없다**(전부 Phase 2로 의도적 보류).

→ 따라서 전략은 **"GenIP 복제"가 아니라 "GenIP의 Phase 2 완성도를 빠르게 따라잡되, 우리만의 Phase 1 moat(리서치·근거·기밀성)와 결합"** 이다. 그리고 다행히 **우리 DB 스키마에 그 Phase 2 테이블(`spec_sections`+`base_generated_text`, `claims`, `exports`)이 이미 다 만들어져 있다.** 즉 따라잡기는 "신규 구축(L)"이 아니라 대부분 "배선 연결(M)"이다.

## 2. 상품성(Commercial Quality) 객관 비교표

격차 = GenIP 대비 우리의 부족/우위. 근거는 실제 파일/스키마.

| 축 | GenIP (영상 관찰) | 우리 현황 (코드 근거) | 격차 |
|---|---|---|---|
| **온보딩/인테이크** | "새 명세서 작성하기" 구조화 입력 | `intake_inputs` + `debrief` 카드 + clarifying Q&A + **§30 공지예외 문진** | **우리 약우위**(§30 클럭) |
| **선행기술 리서치** | 영상에 없음 — 검색/근거 화면 0회 | PubMed+OpenAlex 멀티소스 + dedupe/rank + `coverage_report.blind_spots`("never 100%") | **🟢 우리 압도적 우위** |
| **근거/anti-환각** | grounding 화면 없음 | `lib/llm/grounding.ts` **closed allow-list 검증**, "목록에 없는 번호 절대 생성 금지"(`analyze.ts` SYSTEM) | **🟢 우리 압도적 우위** |
| **명세서 본문 자동생성** | ✅ 원클릭 전체 섹션 생성 | ❌ 없음 — `analyze`는 차별성 분석만, 본문 prose 미생성(`draft-pane.tsx:43,103,189` "Phase 2") | **🔴 GenIP 압도적 우위** |
| **청구항** | ✅ 독립+종속 **실제 청구항 텍스트** + 분석 | ⚠️ `claim_strategy`(전략 한줄)뿐, `claims` 테이블 **비어있음**(`analyze.ts:96`) | **🔴 GenIP 우위** |
| **편집 UX** | ✅ 섹션별 **인라인 AI 편집 툴바** | ❌ `draft-pane` 문서 탭 **read-only**(`statusOf`는 draft/empty만) | **🔴 GenIP 우위** |
| **문서 구조/목차** | ✅ 우측 목차 네비 + 진행맵 | ⚠️ 목차 탭 + click-to-scroll **있음**, 단 `done/검토완료` 상태 미도달(dead code) | **🟡 부분 동등** |
| **도면** | ✅ AI 도면 생성 + 직접 업로드 | ❌ 없음(`intake_inputs.file_path` 스캐폴드만) | **🔴 GenIP 우위(단 우리 명시적 non-goal)** |
| **출력/내보내기** | ✅ 다운로드/export 상단바 | ❌ 없음 — `exports` 테이블·`exported` 상태만 존재(도달 불가) | **🔴 GenIP 우위 — 가장 치명적** |
| **협업 어시스턴트** | Gen-X **플로팅** 챗봇(보조) | 중앙 **채팅이 메인** surface(`api/chat`, ChatContext 주입) | **🟡 동등(형태 차이, 우리는 메인)** |
| **비즈니스 모델** | ✅ 크레딧 과금, 셀프서브 | ❌ 과금 surface 없음 | **GenIP 우위(MVP 비우선)** |
| **기밀성/신뢰** | 불명 | **zero-retention + RLS + dossier=truth + 3-way merge 설계** | **🟢 우리 우위(B2B 핵심)** |
| **전반 완성도** | 상용 판매 제품 | Phase1 완성 MVP shell | **GenIP 우위(현 시점)** |

**요약:** GenIP은 "보이는 산출물"(본문·청구항 텍스트·도면·편집·export)에서 앞서고, 우리는 "신뢰의 근거"(리서치·grounding·커버리지·기밀성)에서 앞선다. 데모에서 지지 않으려면 보이는 산출물(본문+export)을 빠르게 따라잡아야 한다.

## 3. GenIP UI/UX 상세 분해 (영상에서 본 것)

**3-pane 에디터 (좌: 청구항 | 중앙: 본문 | 우: 목차)**

1. **좌측 패널 — 청구항 분석 / 청구 범위 토글**
   - `청구항 분석`: 청구항을 카드로, 품질 스코어/지표 표시.
   - `청구 범위`: 실제 청구항 텍스트(독립항+종속항, "…를 포함하는 … 장치", "제1항에 있어서…"). 각 청구항 우상단 **아이콘 2개(AI 재생성 + 복사)**. 하단에 **MY CREDITS 9,983 + "추가 생성"** 버튼.
   - *왜 좋은가:* 청구항은 권리의 핵심 → 항상 좌측 고정 노출 + 즉시 재생성. 권리범위를 "문서 본문과 분리해" 다루는 게 변리사 멘탈모델과 일치.

2. **중앙 패널 — 명세서 본문(섹션별 인라인 AI 편집)**
   - KIPO 순서대로 전체 섹션 렌더(명칭/기술분야/배경기술/해결과제/해결수단/효과/도면설명/구체적실시/부호설명).
   - 각 섹션·문단에 **hover/select 시 인라인 AI 툴바**(재생성/다시쓰기/확장). 전체가 아니라 **블록 단위** 편집.
   - *왜 좋은가:* "전체 재생성"의 공포 없이 한 문단만 고친다. 사용자가 통제감을 갖는다.

3. **우측 패널 — 목차(아웃라인) 네비게이터**
   - KIPO 구조 트리(발명의 설명 > 하위 / 청구범위 / 요약서 / 도면). 클릭 → 본문 해당 섹션으로 스크롤. 채워진 섹션 진행맵 역할.
   - *왜 좋은가:* 긴 문서에서 길 안내 + "어디까지 됐는지" 진척도.

4. **AI 도면 생성 / 직접 업로드** — 발명 설명에서 선도면(부호 포함) 자동 생성 또는 사용자 업로드. 부호의 설명·도면의 간단한 설명과 연동.

5. **Gen-X AI 어시스턴트** — 우하단 **플로팅 챗봇**. 작업 중 Q&A·편집 보조(보조 surface).

6. **상단 액션바** — 편집 가능한 문서 제목 + 저장/다운로드(export)/AI분석/공유/챗 토글.

7. **크레딧 시스템** — 생성 1회 = 크레딧 차감, "추가 생성"으로 유료 재생성. 명확한 셀프서브 과금.

## 4. 우리 버전에 적용할 것 — 우선순위 로드맵

규칙: **스키마/검증기가 이미 있으면 M, 순수 신규 surface면 L.** (`0001_init.sql`이 cheat-sheet다.)
이 로드맵은 사실상 **컨센서스 플랜의 Phase 2를 "GenIP 수준 UX"로 구현**하는 것 — 새 발견이 아니라 우선순위 확인.

### 🔴 P0 — 상품성 격차 최대 + 임팩트 최고 + 스키마 이미 존재

**P0-A. 명세서 본문 섹션별 생성** (`api/generate/section`) — **난이도 M**
- GenIP의 헤드라인(원클릭 본문). 우리의 가장 큰 가시적 공백.
- **이미 있는 것:** `spec_sections`(+`base_generated_text`) 테이블, `sections.ts`의 KIPO 섹션 구조+guidance, `grounding.ts` 검증기, 선행기술 refs.
- **만들 것:** `api/generate/section` route + `lib/llm` 섹션 prose 생성 task(grounding 통과) + `draft-pane.tsx` 연결(현재 분석결과 렌더 → 실제 본문 렌더).
- **우리 차별화:** GenIP과 달리 **생성 본문이 선행기술 번호로 grounding** 됨 → "근거 있는 본문".
- 영향 파일: `lib/llm/`(신규 task), `app/api/generate/section/route.ts`(신규), `app/_components/draft-pane.tsx`, `lib/kipo/sections.ts`(소비).

**P0-B. DOCX 내보내기** (`api/export`) — **난이도 S~M**
- 변리사 핸드오프의 **필수 산출물**. GenIP 대비 table-stakes. 임팩트 최고/비용 최저 → **가장 먼저 출하**.
- **이미 있는 것:** `exports` 테이블 + `exported` 상태 enum + KIPO 섹션 순서.
- **만들 것:** docx 라이브러리 + KIPO 순서대로 섹션 조립 + 상단바 다운로드 버튼.
- *근거 우위:* 본문이 아직 거칠어도 변리사는 prose는 다듬을 수 있다. 그러나 **내보낼 수 없으면 아예 못 쓴다.** 따라서 완벽한 본문보다 먼저.
- 영향 파일: `lib/export/`(신규), `app/api/export/route.ts`(신규), 상단바 UI.

### 🟡 P1 — 핵심이나 P0 선행 필요

**P1-A. 인라인 섹션 편집 + 재생성 + 3-way merge** — **난이도 L**
- GenIP의 섹션별 인라인 편집. 우리 문서 탭을 **editable**로.
- **만들 것:** 문서 탭 editable(Tiptap 등) + `spec_sections` read/write + **3-way merge truth-table**(현재 설계만 존재) + 충돌 UI.
- 순수 신규 surface라 L. P0-A(본문 생성) 선행 필요.

**P1-B. 실제 청구항 텍스트 생성 + antecedent-basis 가드** (`api/generate/claims`) — **난이도 M~L**
- GenIP의 청구 범위 패널 대응. `claim_strategy`(전략) → 실제 청구항 텍스트.
- **이미 있는 것:** `claims` 테이블, `COMPLIANCE_CHECKS` 상수, `claim_strategy` 사다리(확장 발판).
- **만들 것:** 청구항 prose 생성 + **한국어 형태소 인식 antecedent-basis 검증**(카트리지/카트리지를/카트리지가) → 미스매치 시 export 차단.

**P1-C. 청구항 분석 스코어 카드** — **난이도 M**
- GenIP 좌측 스코어링 대응. `COMPLIANCE_CHECKS`(7개)를 실제 validator 엔진으로 구현 + 좌측 패널 UI.

**P1-D. 목차 진행맵 완성** — **난이도 S**
- `statusOf`가 `done/검토완료`에 도달하도록(현재 dead code) — 섹션 검토완료 플래그. GenIP의 "채워진 섹션 진행맵"과 동등화.

### 🟢 P2 — GenIP에 있으나 우리 전략상 후순위

**P2-A. AI 도면 생성** — **난이도 L, 그리고 명시적 non-goal**
- 컨센서스 플랜 Non-Goals에 "3D/engineering drawing generation … Phase 3" 명기. **GenIP에 있다는 이유로 P0/P1로 올리지 말 것.** medtech 변리사 filing은 도면을 외부 첨부로 처리.
- *단,* **직접 업로드**는 `intake_inputs.file_path`가 있으니 저비용(S~M)으로 가능 — 생성은 미루되 업로드는 고려 가능.

**P2-B. 크레딧/과금** — **난이도 M, MVP 비우선**
- 첫 목표는 내부 검증(혈청 안약 안경)이지 유료고객이 아님. GenIP의 과금 성숙도에 끌려 올리지 말 것. `usage_log`로 내부 비용 가시화는 이미 가능.

### 적용 금지 주의 (안티패턴)
- **"GenIP 모든 패널 1:1 복제"를 목표로 삼지 말 것.** 컨센서스 플랜 원칙 5: "리서치 엔진(가치 코어)을 완벽한 명세서 포매팅보다 먼저." UI 패널 패리티를 리서치/grounding 코어보다 우선하면 **우리 전략적 우위를 뒤집는 것.**

## 5. 차별화 전략 (단순 카피 금지)

1. **"근거 있는 초안"이 wedge.** GenIP은 원클릭 생성하지만 그 본문/청구항의 **선행기술 근거가 없다**(영상에 리서치/근거 화면 0). 우리는 *생성 전에* 리서치 → grounding → 생성. 본문/청구항의 모든 주장에 선행기술 번호가 달린다. → **"환각 없는, 변리사가 신뢰하는 초안."** 이걸 UI로 보이게: 각 섹션 옆 "이 문장의 근거 선행기술 보기" 칩(우리 grounding과 직결, GenIP이 못 하는 것).

2. **기밀성/zero-retention을 전면에.** 미공개 발명 = 신규성 민감 자산. LLM+임베딩 zero-retention + RLS. medtech B2B 클라이언트엔 결정적 구매 사유. GenIP(공개 셀프서브)이 내세우기 어려운 포인트.

3. **한국 실무 디테일 = 변리사급 신뢰.** §30 공지예외 클럭(`disclosure.ts`/`computeGrace`), 한국어 형태소 antecedent-basis 가드, 정직한 coverage("never 100%" + blind_spots). GenIP에 보이지 않는 "변리사가 챙기는 디테일."

4. **그러나 "보이는 완성도"는 반드시 따라잡는다.** moat가 있어도 데모에서 본문/청구항/export가 없으면 진다. → 그래서 P0가 본문생성 + DOCX export. **moat(Phase 1) + 가시적 완성도(Phase 2 따라잡기)의 결합**이 최종 포지션.

## 6. 즉시 다음 액션 (추천 순서)

1. **P0-B DOCX export** 먼저 (S~M, 스키마 존재, 임팩트 최고). 변리사에게 "넘길 수 있는" 산출물 확보.
2. **P0-A 섹션별 본문 생성** (M, grounding 결합). GenIP 헤드라인 따라잡기 + 우리 근거 우위 결합.
3. 그 다음 P1-A 인라인 편집 / P1-B 청구항 텍스트로 GenIP 에디터 패리티.
4. 도면 생성(P2-A)·과금(P2-B)은 검증 마일스톤 이후.

> 결론: 우리는 GenIP의 "Phase 2"가 비어 보이지만 **DB 스키마는 이미 Phase 2를 위해 설계돼 있고**, GenIP에 없는 "Phase 1 리서치/근거 moat"를 이미 갖췄다. 따라잡기는 신규 구축이 아니라 배선이며, 따라잡은 뒤의 제품은 GenIP보다 **방어 가능**하다.
