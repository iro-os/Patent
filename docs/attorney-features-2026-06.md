# 변리사 편의 기능 — 리서치·기획 (2026-06-12)

> 질문: "이 앱을 **변리사가** 사용하면 더 편리해질 기능은 무엇인가?"
> 현재 앱은 발명자(비전문가) 중심: 대화 → 선행조사 → 본문 생성 → DOCX. 변리사는 다른 것을 원한다 —
> **검증·검수 도구**다. 변리사 검토 우선순위(이전 리서치): ① 청구항(권리범위·뒷받침·명확성)
> ② 진보성(§29②) ③ 기재불비(§42③④). 이 문서는 풀 리스트업 + 우선순위 + 이번 브랜치 빌드 범위.

## 2. 이번 브랜치 빌드 범위 — "변리사 검토 워크벤치"

**선정: A1 + A2 + A3 + A4 + B1 + C1 + D1** — 하나의 일관된 패키지("검토" 탭).
선정 이유: ① 변리사 1순위(청구항)를 직격, ② 스키마(`claims`·`locked`)와 상수(`COMPLIANCE_CHECKS`)가
이미 존재해 "새 건축"이 아니라 "배선", ③ 결정론 검사 위주라 LLM 비용·환각 리스크 낮음,
④ 기존 moat(grounding·정직성)와 동일 철학 — **검사 결과도 근거(조문·위치)와 함께 제시**.

### 인터랙션 설계
- 오른쪽 패널에 **셋째 탭 "검토"**: ① 컴플라이언스 리포트 카드(7종 체크, 통과/주의/실패 + 해당 위치로 점프)
  ② 청구항 워크벤치(에디터 + **라이브 린트**(타이핑 즉시, 클라이언트 결정론) + AI 초안 버튼 + 저장).
- 문서 탭: 섹션 표제 옆 **"검토 완료" 토글**(lock). 잠긴 섹션은 재생성·되돌리기 불가(서버 이미 강제),
  목차 점이 초록으로.
- 청구항이 저장되면 문서 탭·DOCX의 【청구범위】에 실제 청구항 텍스트 렌더 +
  "변리사 검토 필요" 고지 유지. 미저장 시 기존 전략 블록 fallback.

### 린트 룰 (법적 근거 명시)
| 룰 | 근거 | 강도 |
|----|------|------|
| 청구항 1 = 독립항 | 실무 원칙(첫 항 독립) | error |
| 인용은 앞 번호만 | 시행령 §5⑥ | error |
| 존재하지 않는 항 인용 | — | error |
| 다중종속항이 다중종속항 인용 금지 | 시행령 §5⑤ | error |
| 2개 이상 인용은 택일적("또는") 기재 | 시행령 §5④ | warn |
| "상기 X" 선행사 미기재 | §42④2 (명확성) | warn (휴리스틱) |
| 불명확 표현(약·대략·등·바람직하게는…) | §42④2 심사기준 | warn |
| 청구항 용어 명세서 미뒷받침 | §42④1 | warn (휴리스틱) |

휴리스틱 룰은 "주의"로만 표시하고 **확정 판단은 변리사**임을 UI에 명시(기존 면책 철학 유지).

### Non-goals (이번 범위 밖)
A5 대비표, B2 용어 일관성, B3 도면부호, C2 이력 뷰, C3 코멘트, D2 출원서, D3 도케팅,
형태소 분석기 도입(휴리스틱 토큰화로 시작), 새 마이그레이션(기존 스키마로 충분).
